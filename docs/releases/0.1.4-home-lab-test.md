candidate `0.1.4-rc.2`. It is an **upgrade** test of the running, Flux-managed
deployment (0.1.3 → 0.1.4-rc.2). This candidate is also the one the final
`0.1.4` is **promoted** from (ADR 0005): the final tag must publish this exact
image digest without a rebuild. No secret value appears in this report;

counts only.

candidate, job-graph check, pinned and Renovate-tracked tool versions, escaped
registry output), the SPDX `WITH` parse error in `xtask`, and documentation. The
operator code is unchanged; the image label `version` is now `0.1.4`.

**Flux ordering delay.** As in the 0.1.3 test, the first `flux reconcile
kustomization secretspec-operator --with-source` hit its 90 s timeout
("context deadline exceeded"): the dependency chain (`authentik`,
`victoria-metrics`) still sat on the previous revision. A plain `flux reconcile
kustomization` of `authentik`, `victoria-metrics` and `secretspec-operator` in
turn applied revision `5f463cf` and the HelmRelease upgraded within seconds. This
is GitOps-repository/Flux behaviour, not an operator effect; nothing else was
changed.

### Conflict requeue timings (scenario a)

UTC, 2026-11-01. A plain, unlabelled Secret `dashboard-auth` (one literal key)
was created in `test-secretspec` before the `traefik-basic-auth` example
(SecretSpec `dashboard-auth`) was applied.

| Time | Event |
|---|---|
| 23:14:59 | All 7 examples applied. Operator log 23:14:59.71: `dashboard-auth` reconciled with `action=Nothing`, `ready_reason=Conflict`. The foreign Secret was left untouched. |
| 23:15:59 … 23:25:00 | Retry reconciles every 60 s, all `Conflict` (the foreign Secret was still there; see note). |
| between 23:25:00 and ≈ 23:25:19 | Foreign Secret deleted. |
| 23:26:00 | `Ready=True` (`lastTransitionTime`); operator log 23:26:00.40: `reconciled … dashboard-auth action=Apply ready_reason=Generated`, reason "reconciler requested retry". New Secret created at 23:26:00. |

Recovery took **41–60 s** after the deletion (the next 60 s requeue after
23:25:00; the delete was issued after the 23:25:00 retry had seen `Conflict`),
so well within 90 s. No restart, edit or manual nudge was needed.

*Note on timing precision.* The delete command was issued in the same parallel
batch as a `date` call and the shell tool only executed it about ten minutes
later; the `Conflict` retries until 23:25:00 in the operator log show this. The
exact deletion second is therefore not known; the bounds above come from the
operator log (last `Conflict` at 23:25:00.04) and the next requeue.

### Log-leak check (scenario i)

The first generation of `garage/rpc-secret`, `dashboard-auth` and
`shared-token` was replaced by scenarios d, e and g before a pattern file had
been built, so those values could no longer be read. To still test the log
lines that the regeneration paths produce against real values, the pattern file
`A` was built from the then-current values, and then scenarios d, e and g were
repeated once (delete the `garage` key, delete the `dashboard-auth` Secret,
rotate `shared-token`), which replaced exactly those values. Pattern file `B`
was built afterwards. Both files, against the pre-restart log, the post-restart
log taken after the repeat, and the final log: **0 matching lines**. As a
positive control, the two pattern files share 21 lines (the unchanged values),
so the matching technique does find values when they are present. Only counts
were printed; the pattern files were written by redirect.

## Deviations and notes

- **Flux dependency chain** delayed the rollout (see "Flux ordering delay");
  resolved by extra `flux reconcile kustomization` calls on `authentik` and
  `victoria-metrics`, as in the 0.1.3 test.
- **Conflict timing** is a 41–60 s bound, not a measured second (see the timing
  note).
- **Log-leak check** needed scenarios d, e and g to be repeated once (see
  "Log-leak check"); the first generation of those three values was not covered
  by a pattern.
- **Scenario f:** the `resourceVersion` of `app-admin` changes on adoption; the
  values do not.
- **`LowEntropy` Warning Event** on `garage` (`access-key-id`, 96 bits) from the
  example, as designed.
- The HTTP chart repository was exercised by the Flux upgrade path; the OCI
  chart was exercised only through `cosign verify`.
- The documentation commands (`docs/installation.md` cosign commands) worked
  as written (with the variables expanded to literal values).
