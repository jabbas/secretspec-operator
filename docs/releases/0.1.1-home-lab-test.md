### Conflict requeue timings (scenario 4)

Sequence (UTC, 2026-10-25): a plain, unlabelled Secret `dashboard-auth` was
created in `test-secretspec` before the `traefik-basic-auth` example (SecretSpec
`dashboard-auth`) was applied.

| Time | Event |
|---|---|
| 22:48:53 | Examples applied. |
| 22:49:01 | `dashboard-auth` is `Ready=False`, reason `Conflict`: `Secret dashboard-auth exists and is not managed by this SecretSpec`. The foreign Secret was left untouched (no operator labels, only its own key). |
| 22:49:07 | Foreign Secret deleted. |
| 22:49:58 | `Ready=True` observed (poll every 5 s): **51 s** after the deletion, about 65 s after the first Conflict. Event `Generated: generated keys: password, users`; Secret carries the operator labels. |

The recovery fits the 60 s requeue (deletion at a random point of the cycle, so 0–60 s
plus poll granularity); no restart, no edit of the `SecretSpec` and no manual
nudge was needed.

## Teardown

Run in this order, with `--context`/`--kube-context admin@k8s`:

1. `helm uninstall secretspec -n test-secretspec` — released; the CRD was kept (`crds.keep`).
2. `kubectl delete namespace test-secretspec --wait` — gone (`NotFound`).
3. `kubectl delete crd secretspecs.secretspec.jabbas.eu` — deleted; only this CRD.
4. `kubectl get secrets -A -l app.kubernetes.io/managed-by=secretspec-operator` → `No resources found`.
5. No ClusterRole/ClusterRoleBinding, namespace, Helm release or CRD matching `secretspec` remains.

## Deviations and notes

- **Licence bundle was read from the image, not via `kubectl exec`.** The image
  has no shell or `ls` (`exec: "ls": executable file not found`), so
  `kubectl exec … ls /licenses` is impossible. The bundle was listed with
  `crane export` of the same digest the pod runs (`linux/amd64`), read-only and
  local. The cluster was not touched for this check.
- **The HTTP chart repository (`https://jabbas.github.io/helm-charts`) was not
  exercised**; the install used the OCI chart as the plan said.
- The git/image tag and chart version are the plain semver `0.1.1-rc.1` (no
  `v`); the cosign identity uses `refs/tags/0.1.1-rc.1`, as `docs/installation.md`
  describes for 0.1.1 and later.
- Documentation commands from `docs/installation.md` and `docs/operations.md`
  worked as written; no other deviation.
