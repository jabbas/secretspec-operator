# 0.1.3-rc.2 home-lab test report

Home-lab test procedure of the design (§12), run against the published release
candidate `0.1.3-rc.2`. It is an **upgrade** test of the running, Flux-managed
deployment (0.1.2 → 0.1.3-rc.2) and adds one new scenario (j): a namespace
holding SecretSpecs is deleted, and the operator must stay quiet. No secret
value appears in this report; comparisons are equal/changed verdicts or match
counts only.

What changed since 0.1.2:

- A Secret apply rejected with 403 cause `NamespaceTerminating` now logs one
  `debug` line and does nothing more: no `ApplyFailed` status, no events, no
  retry. In the 0.1.2 test, deleting the namespace produced 15 `WARN` lines.
- The CRD no longer has `format: uint16`; the bounds are unchanged.

## Upgrade path 0.1.2 → 0.1.3-rc.2 via Flux

The only change in the GitOps repository was `version: "0.1.2"` →
`version: "0.1.3-rc.2"` in the HelmRelease (direct commit `01312d0` on
`main`). `flux reconcile source helm jabbas` fetched the new index, then
`flux reconcile kustomization secretspec-operator --with-source`.

| Check | Result |
|---|---|
| HelmRelease | PASS — `Helm upgrade succeeded for release secretspec-system/secretspec-operator.v4 with chart secretspec-operator@0.1.3-rc.2` |
| Rollout | PASS — new pod `1/1 Ready`, 0 restarts, image `:0.1.3-rc.2`, image ID `sha256:dd4bd53b…` (the cosign-verified index digest) |
| CRD | PASS — `grep -c uint16` prints `0`; `helm.sh/resource-policy: keep` kept; version `v1alpha1`; chart label `0.1.3-rc.2` |
| Metrics scrape | PASS — ServiceMonitor present, converted `VMServiceScrape` status `operational` |
| Operator log | PASS — startup, API discovery succeeded, "standing by" while the old pod held the Lease, `acquired leadership` 5 s later, `controllers started` (scope `cluster`); 0 `WARN`/`ERROR` lines for the whole run |

**Flux ordering delay.** The first `flux reconcile kustomization
secretspec-operator --with-source` did not finish within 2 minutes: the
Kustomization `dependsOn` `victoria-metrics`, which waited on `authentik`,
which waited on `cloudnativepg`. Those three still showed the previous
revision (`8e99d873`) and `Ready=False` ("dependency … is not ready") even
though `cloudnativepg` was already Ready at the new revision. Three plain
`flux reconcile kustomization` calls (`authentik`, `victoria-metrics`,
`secretspec-operator`) unblocked the chain; each applied the new revision
immediately and the HelmRelease upgraded within seconds. This is
GitOps-repository/Flux behaviour, not an operator effect; nothing else was
changed.

**Version string.** The startup log line says `"version":"0.1.3"` for the
`0.1.3-rc.2` image (the binary reports the crate version without the
pre-release suffix), as it did for `0.1.2-rc.1`.

### Conflict requeue timings (scenario a)

UTC, 2026-11-01. A plain, unlabelled Secret `dashboard-auth` (one key) was
created in `test-secretspec` before the `traefik-basic-auth` example
(SecretSpec `dashboard-auth`) was applied.

| Time | Event |
|---|---|
| 12:32:57 | All 7 examples applied. Operator log: `dashboard-auth` reconciled with `action=Nothing`, `ready_reason=Conflict` (12:32:57.80). The foreign Secret was left untouched. |
| ≈ 12:33:04 | Foreign Secret deleted (wall clock read in the same call batch, accuracy about ±1 s). |
| 12:33:57 | `Ready=True` (`lastTransitionTime`); operator log 12:33:58.09: `reconciled … dashboard-auth action=Apply ready_reason=Generated`, reason "reconciler requested retry". Event `Generated: generated keys: password, users`. |

Recovery was ≈ **53 s** after the deletion and exactly 60 s after the
Conflict was recorded, i.e. the 60 s requeue; no restart, no edit and no
manual nudge was needed.

absence of noise but does not by itself exercise the new 403 code path.

## Deviations and notes

- **Flux dependency chain** delayed the rollout (see "Flux ordering delay");
  resolved by extra `flux reconcile kustomization` calls on `authentik` and
  `victoria-metrics`.
- **Conflict timing** is derived from the Ready transition and the operator
  log; the deletion time is accurate to about ±1 s.
- **Scenario g** needed no wait for the nominal rotation time: as designed, the
  back-dated `generated-at` annotation makes the rotation due, and the Secret
  watch picked it up immediately.
- **`LowEntropy` Warning Event** on `garage` (`access-key-id`, 96 bits) from the
  example, as designed.
- The HTTP chart repository was exercised by the Flux upgrade path; the OCI
  chart was exercised only through `cosign verify`.
- The documentation commands (`docs/installation.md` cosign commands) worked
  as written.
