# 0.1.5-rc.1 home-lab test report

Home-lab test procedure of the design (§12), run against the published release
candidate `0.1.5-rc.1`. It runs against the Flux-managed deployment, which was
already on the rc when this run started (HelmRelease `secretspec-operator`,
release revision v8). This candidate is also the one the final `0.1.5` is
**promoted** from (ADR 0005): the final tag must publish this exact image digest
without a rebuild. No secret value appears in this report; comparisons are
equal/changed verdicts, short digests of stored values, or match counts only.

What changed since 0.1.4: the operator source is unchanged apart from
dependencies. This is the **first release on kube 5 and k8s-openapi 0.29**, and
the first one whose **chart is packaged with Helm 4**. So this test is mainly a
check that the dependency jump and the new chart packaging behave like 0.1.4 on
a real cluster (install through Flux, CRD, RBAC, metrics scrape, all scenarios).
The image label `version` is now `0.1.5`.

**Interrupted first attempt.** A first run of this test was interrupted by a
tooling (server) restart. The rc bump had been committed and pushed and the rc
was deployed by then, but no scenario results were recorded. Nothing from that
attempt is counted: the leftover namespace `test-secretspec` (7 SecretSpecs, all
`Ready`, about 3 days old, so it predates the rc bump; no SecretSpec existed in
any other namespace) was deleted, and **every scenario below was rerun in full**
from a fresh namespace.

### Conflict requeue timings (scenario a)

UTC, 2026-11-11. A plain, unlabelled Secret `dashboard-auth` (one literal key)
was created in `test-secretspec` before the `traefik-basic-auth` example
(SecretSpec `dashboard-auth`) was applied.

| Time | Event |
|---|---|
| 21:38:08.48 | All 7 examples applied. Operator log: `dashboard-auth` reconciled with `action=Nothing`, `ready_reason=Conflict`. The foreign Secret was left untouched. |
| ≈ 21:38:11 | Foreign Secret deleted (shell `date` taken right after the delete: 21:38:12). |
| 21:39:08.99 | Operator log: `reconciled … dashboard-auth action=Apply ready_reason=Generated`, reason "reconciler requested retry"; `Ready=True` (`lastTransitionTime` 21:39:08). |

Recovery took **≈ 57 s after the deletion** (60.5 s after the first `Conflict`):
the 60 s requeue after the `Conflict`, well within 90 s. No restart, edit or
manual nudge was needed. The deletion of the foreign Secret did not trigger an
earlier reconcile; the recovery came with the scheduled requeue.

### Log-leak check (scenario i)

The pattern files were written by redirect (only counts were ever printed).
Set A was built once all 7 SecretSpecs were Ready and **before** scenarios d, e
and g replaced values; set B was built after g. A therefore covers the values
that d, e and g replaced, B covers the values they produced; the pre-restart log
and the post-restart log (which contains the regeneration, adoption and
rotation reconciles) were each matched against both sets, raw and base64.
Result: **0 matching lines** in all eight combinations, and 0 `WARN`/`ERROR`/
`ApplyFailed`/"reconcile failed" lines in either log. Positive control: A and B
share 11 decoded lines.

The pre-restart log is the whole log of the first pod from its start (it also
contains reconciles of the interrupted first attempt's objects; those values
are not covered by the patterns).

## Deviations and notes

- **Interrupted first attempt** (see the top): the leftover namespace
  `test-secretspec` was deleted and all scenarios were rerun in full.
- **No Flux reconcile was needed**: the HelmRelease was already at
  `0.1.5-rc.1` when this run started, so there was no ordering delay to
  report this time.
- **Conflict timing** is derived from the operator log and the shell `date`
  taken after the delete (≈ 57 s), not from a measured delete second.
- **Log-leak check:** pattern sets A and B were built around d, e and g, as
  the 0.1.4 report did, but without having to repeat the scenarios.
- **Scenario f:** the `resourceVersion` of `app-admin` changes on adoption; the
  values do not.
- **`LowEntropy` Warning Event** on `garage` (`access-key-id`, 96 bits) from the
  example, as designed.
- The HTTP chart repository was exercised by the Flux upgrade path (earlier,
  before this run); the OCI chart was exercised through `cosign verify`.
- The documentation commands (`docs/installation.md` cosign commands) worked
  as written (with the variables expanded to literal values).
