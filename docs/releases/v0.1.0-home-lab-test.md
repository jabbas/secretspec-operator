## Findings

1. **`NEXT ROTATION` column shows `<invalid>` (cosmetic).** In `kubectl get
   secretspec`, the printer column `.status.nextRotationTime` (type `date`) is
   rendered as `<invalid>` with kubectl v1.37.1, because kubectl formats `date`
   columns as an age and a time in the future yields a negative duration.
   `status.nextRotationTime` itself is correct (checked with `-o jsonpath`).
   `docs/operations.md` ("Scheduled rotation") says the next rotation is
   "visible in the `NEXT ROTATION` column"; that is not true in practice. Suggested follow-up for the next release: change the column type to
   `string` in the CRD, or document `-o jsonpath` as the way to read it. This is
   not a functional failure and does not block `v0.1.0`.
2. **Documentation commands.** Every command taken from `docs/installation.md`
   (cosign verify of image and chart, namespace creation and PSA label, `helm
   install … --version`, `rollout status`, `kubectl get crd`) and from
   `docs/operations.md` (delete a Secret, remove one key by JSON patch) worked
   as written. Deviations: none besides finding 1. The documented Deployment
   name for a release not containing `secretspec-operator`
   (`<release>-secretspec-operator`) was correct
   (`secretspec-secretspec-operator`).
